# قائمة تدشين أرسو (الإنتاج)

الحالة: **بيئة الاختبار تعمل** على `web-staging-ec25.up.railway.app`. الإنتاج لا يُفتح للتجار قبل إكمال البنود المعلّمة 🔴.

## 1. ما يفعله المالك

| # | البند | الخطوات | لماذا |
|---|---|---|---|
| 🔴 1 | **الدومين `arso.sa`** | الشراء من مسجل معتمد لنطاق `.sa` (مثل SaudiNIC عبر وكيل معتمد). بعد الشراء: أرسل اسم الدومين فقط | روابط التأكيد والبريد وثقة التاجر |
| 🔴 2 | **حساب Resend** | resend.com ← Domains ← Add `arso.sa` ← انسخ سجلات DNS التي يعرضها (SPF وDKIM وMX للإرجاع) إلى لوحة الدومين ← انتظر «Verified» ← API Keys ← أنشئ مفتاحًا بصلاحية Sending فقط ← ضعه **بنفسك** في Railway: مشروع arso ← بيئة production ← خدمة api ← Variables ← `RESEND_API_KEY`. **لا ترسل المفتاح في المحادثة** | بدون بريد لا يستطيع أي تاجر تأكيد حسابه |
| 🔴 3 | **مراجعة قانونية** | محامٍ يراجع `/privacy` و`/terms` (مسودتان كتبهما Claude بناءً على ما يفعله النظام فعلًا)، خاصة نقل البيانات خارج المملكة (الاستضافة في ألمانيا وهولندا) وفق نظام حماية البيانات الشخصية | التزام نظامي قبل جمع بيانات التجار |
| 🔴 4 | **بريدان للتواصل** | `privacy@arso.sa` و`support@arso.sa` (يمكن تحويلهما لبريدك). أخبرني بهما لأستبدل `[بريد الخصوصية]` و`[بريد الدعم]` | حقوق صاحب البيانات تحتاج قناة |
| 🟠 5 | تطبيق سلة | Client ID فقط | الربط المباشر بدل الملفات |
| 🟠 6 | سياسة الأسعار | الاشتراك المجاني في التجربة أو باقة | صفحة التسعير والفوترة لاحقًا |

## 2. ما يفعله Claude بعد البندين 1 و2

1. **قاعدة إنتاج منفصلة:** فرع Neon جديد `production` نظيف (بلا بيانات الاختبار)، وكلمات مرور جديدة لأدوار `arso_app` و`arso_auth` تُكتب مباشرة في متغيرات Railway ولا تُعرض، وتفعيل الاستعادة لنقطة زمنية.
2. **بيئة Railway `production`:** خدمتا web وapi من فرع `main` بالإعداد نفسه، و`NODE_ENV=production` و`DEPLOY_ENV=production` و`PUBLIC_WEB_URL=https://arso.sa`، وسر جلسات جديد.
3. **الدومين:** ربط `arso.sa` و`www.arso.sa` بخدمة web، وشهادة HTTPS تلقائية، وتوجيه www إلى الجذر.
4. **المراقبة:** مشروع Sentry للإنتاج، وتنبيه عند فشل الصحة أو ارتفاع الأخطاء.
5. **اختبار قبول على الإنتاج:** تسجيل حقيقي ببريد حقيقي، وتأكيد، وإنشاء مؤسسة ومتجر، واستيراد ملفات، وعرض الفرص، ثم حذف حساب الاختبار.
6. **تثبيت الإصدار:** وسم `v1.0.0-beta` على `main`، وملاحظات الإصدار.

## 3. فحوص جاهزية مكتملة في الكود

- عزل المؤسسات داخل القاعدة (RLS مفروض) واختبارات عزل لكل جدول.
- صلاحيات دقيقة لكل متجر، والأرقام المالية تُحذف من الرد لمن لا يملكها (AC02).
- تأكيد البريد إلزامي، وجلسات HttpOnly من نفس الأصل، وTOTP جاهز في الخادم.
- رؤوس أمان: CSP مغلقة، وHSTS في الإنتاج، وX-Frame-Options، وnosniff.
- السجل المالي والتكاليف وسجلات التدقيق append-only.
- الإنتاج يرفض الإقلاع بلا مزود بريد أو بلا https (فحص الإعداد عند البدء).
- مراجعة أمنية لكل تغيير يمس الصلاحيات أو المال أو الملفات.

## 4. ما لا يُدَّعى عند التدشين

الموقع والإعلانات تذكر المتاح فقط: الاستيراد بالملفات، والنظرة العامة بشارات الجودة، والمشكلات والفرص، والمهام، والفريق والصلاحيات. ربط سلة المباشر والتجارب والتنفيذ على منصات الإعلان **قيد البناء** وتُذكر كذلك.

# خطة بناء أرسو

> المبدأ الحاكم (الوثيقة، الخاتمة): **دورة كاملة صحيحة قبل أي قدرة جديدة.** تبدأ ببيانات قابلة للمطابقة، وتنتهي بإجراء ونتيجة محفوظة.

## الخريطة

```
المرحلة 0: التأسيس والموافقات   ← الآن، بالتوازي
E0: إثبات الوصول
E1-A: الشريحة الرأسية الأولى (سلة + سناب + تكاليف + نظرة عامة + صحة البيانات)
E1-B: التشخيص والمهام والتجارب والتقارير
E1-C: الاستوديو والرادار والموقع العام
بوابة E1 ← تجربة وريف (W09)
E2: التنفيذ مع الاعتماد
E3: الرحلات والشبكة والنقد
E4: التوسع
```

### ما يبنيه Claude (W00 وW03)
- مستودع بهيكل monorepo، وCI (lint وtypecheck واختبارات وbuild)، وقالب PR.
- مشروع Neon بفرع لكل PR، ومشروع Sentry، وخدمات Railway (web وapi وworker) لبيئة الاختبار.
- أساس الهوية: tokens، والخطوط، ومكتبة المكونات الأساسية (بطاقة مقياس، شارة جودة، جدول، معالج، حالات الصفحة الخمس).
- Identity/Tenancy: المؤسسات والمتاجر والعضويات والمنح والصلاحيات الدقيقة، وسجل التدقيق.
- **اختبارات العزل أولًا** (`TENANT-001`): لا ميزة تُدمج قبل أن تمر.

## E0: إثبات الوصول
- موصل سلة: OAuth وstate أحادي الاستخدام، واستيراد طلبات وبنود ومنتجات ومتغيرات ومخزون بصفحات قابلة للاستئناف، وwebhooks موثقة بصندوق وارد دائم.
- موصل سناب: OAuth، وقراءة الحسابات والحملات، وتقرير إنفاق يومي.
- **سجل القدرات** لكل مصدر: الإصدار، والصلاحيات، والحدود، والحقول المتاحة وغير المتاحة.
- **بوابة الخروج:** مطابقة عينة طلبات وإنفاق من وريف مع تقارير سلة وسناب الرسمية. (أداة سلة المتصلة بـ Claude تُستخدم للمطابقة.)

## E1-A: الشريحة الرأسية الأولى
**الهدف:** تاجر يربط متجره وسناب، يضيف تكاليفه، ويرى نظرة عامة صادقة بشارات الجودة.
- معالج الإعداد (القسم 10) قابل للحفظ والاستئناف.
- استيراد CSV للتكاليف والطلبات والإنفاق (الملحق ب).
- محرك اقتصاد الطلب والسجل المالي (القسمان 31 و33). **مثال القسم 33 يصبح اختبارًا إلزاميًا.**
- قاموس المقاييس (القسم 30) بإصدارات ولقطات.
- صفحة النظرة العامة (القسم 13) وصفحة صحة البيانات.
- **اختبارات القبول:** AC01 وAC03 وAC04 وAC05 وAC10 وAC14 وAC15.

## E1-B: من الفهم إلى الفعل
- قواعد التشخيص Q01 إلى Q08 بإصدارات وإزالة تكرار.
- المشكلات والفرص (أهم 3)، والمهام، والتجارب بالنضج، والتقارير والتصدير الآمن.
- المنتجات والمتغيرات، والعملاء والأفواج.
- **اختبارات القبول:** AC02 وAC12.

## E1-C: الإبداع والواجهة العامة
- الاستوديو النصي (3 أفكار)، والرادار اليدوي مع حماية SSRF.
- الموقع العام بالمحتوى في `docs/marketing/ARSO_Copy_AR.md`. **فقط المزايا المتاحة فعلًا.**
- تقييم الذكاء الاصطناعي: أرقام مخترعة، وادعاءات غير موثقة، وحقن تعليمات. **AC11.**

## بوابة E1 (القسم 57)
كل اختبارات الحساب تنجح • صفر خلل عزل معروف • مراجعة مالية لعينة • صور حقيقية لحالات empty وpartial وerror • استيراد قابل للاستئناف • إلغاء الربط • صلاحيات الحقول • استعادة نسخة احتياطية مختبرة • موقع لا يَعِد بغير المتاح.
**ثم:** تجربة على متجر وريف، ثم متاجر مستقلة.

## E2 وما بعدها
تُفصّل بعد بوابة E1 وفق القسم 54 (W10–W13)، ولا يُبنى زر تنفيذ خارجي قبل بوابة E2.

## طريقة العمل
- كل متطلب يتحول إلى Issue برقم `ARSO-<AREA>-<NNN>` (القسم 59).
- كل PR يذكر الـ tickets والمقاييس والإصدارات التي تغيّرت، ويمر بـ CI و`/code-review`.
- كل PR يمس الصلاحيات أو المال أو OAuth يمر بـ `/security-review`.
- كل انحراف عن الوثيقة يُسجَّل في ADR.
